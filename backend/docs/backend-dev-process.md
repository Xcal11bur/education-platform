# 教育云平台后端开发流程

## 1. 开发目标

当前阶段先完成教育云平台后端一期，重点是把课程主链路跑通，确保可以支撑：

- 平台管理员维护教师、分类、课程、章节、资料、考试/作业
- 学员注册登录、查看课程、提交评价、提交考试/作业
- 教师后续具备独立维护课程内容的能力

建议一期先按 “后台管理可维护 + 前台可读取” 作为验收标准，不要一开始就把直播、支付、消息等外围能力一起做进来。

---

## 2. 推荐技术方案

### 2.1 基础栈

- `Spring Boot 3.x`
- `MySQL 8.x`
- `Spring Web`
- `Spring Validation`
- `Spring Security + JWT`
- `MyBatis-Plus` 或 `MyBatis`
- `Lombok`
- `Knife4j / springdoc-openapi`
- 一期暂不引入 `Redis`

### 2.2 工程分层建议

建议单体后端先按标准分层，避免前期过度拆微服务。

```text
com.education.platform
├── common           # 通用返回、异常、工具、枚举
├── config           # 安全、跨域、MyBatis、OpenAPI配置
├── auth             # 登录注册、JWT、权限
├── member           # 会员模块
├── teacher          # 教师模块
├── course           # 分类、课程、章节、资料、评价
├── task             # 考试/作业模块
├── infrastructure   # 文件存储、第三方适配
└── admin            # 后台聚合接口或管理能力
```

### 2.3 包结构规范

每个业务模块建议统一包含：

- `controller`
- `service`
- `service.impl`
- `mapper`
- `entity`
- `dto`
- `vo`
- `convert`
- `enums`

## 3. 开发阶段划分

## 第一阶段：项目骨架搭建

目标：把工程跑起来，并具备统一的基础能力。

开发内容：

- 初始化 `Spring Boot` 工程
- 配置开发、测试环境
- 接入 `MySQL`
- 统一响应体 `Result<T>`
- 全局异常处理
- 参数校验机制
- 日志规范
- OpenAPI/Knife4j 文档
- JWT 登录认证框架
- 基础权限模型

交付物：

- 可启动项目
- 基础接口可访问
- Swagger 文档可打开

## 第二阶段：账号与权限基础

目标：先打通系统里的“谁能访问接口”。

开发内容：

- 管理员登录
- 会员注册/登录
- 教师登录
- 当前登录用户信息接口
- 登录态拦截器或 Security 过滤器
- 角色枚举：`ADMIN`、`TEACHER`、`MEMBER`

关键注意点：

- 密码必须加密存储，推荐 `BCrypt`
- Token 要带角色、用户ID
- 后台和前台接口分路径隔离

交付标准：

- 不同角色可以登录
- 无权限访问可正确返回 `401/403`

## 第三阶段：基础主数据建设

目标：先把平台的基础资料维护能力做起来。

开发顺序：

1. 教师模块
2. 课程分类模块
3. 会员模块后台管理

开发内容：

- 教师增删改查
- 分类树增删改查
- 会员后台分页查询、状态管理

关键注意点：

- 二级分类必须限制最大层级为2
- 删除分类前校验是否被课程引用
- 教师手机号、邮箱建议唯一

交付标准：

- 管理员可以完整维护教师与分类
- 会员信息可后台查询和禁用

## 第四阶段：课程主链路

目标：完成课程从创建到前台展示的核心链路。

开发顺序：

1. 课程基本信息
2. 课程章节
3. 前台课程列表/详情

开发内容：

- 新建课程、编辑课程、上下架
- 课程关联教师和二级分类
- 新建章节与小节
- 查询课程章节树
- 前台课程列表、课程详情聚合接口

关键注意点：

- 课程上架前要校验教师、分类、封面、章节是否齐全
- 章节排序和小节排序要支持拖动后重排
- 课程详情接口尽量做聚合，减少前端多次请求

交付标准：

- 后台可完整维护课程
- 前台可查看课程详情和章节树

## 第五阶段：课程扩展能力

目标：补齐课程运营需要的资料和评价。

开发顺序：

1. 课程资料
2. 课程评价

开发内容：

- 上传课程资料元信息
- 前台资料列表
- 学员提交评价
- 后台审核评价
- 课程评分统计

关键注意点：

- 文件上传建议先对接对象存储，不直接落本地磁盘
- 评价要校验同一用户是否重复提交
- 匿名评价只隐藏前台展示姓名，不影响后台审计

交付标准：

- 课程资料可管理、可展示
- 评价流程可闭环

## 第六阶段：考试/作业

目标：补齐课程学习过程中的考核能力。

开发顺序：

1. 任务基本信息
2. 题目录入
3. 学员提交
4. 批改与成绩查询

开发内容：

- 创建考试/作业
- 题目录入
- 学员提交答案
- 客观题自动判分
- 主观题后台批改
- 提交记录查询

关键注意点：

- 考试和作业先统一抽象，避免表结构重复
- `简答题/作业附件` 的评分要支持人工批改
- 提交记录要保留原始答案，避免覆盖

交付标准：

- 平台可发布考试/作业
- 学员可提交并查看成绩

## 4. 数据库开发流程

### 4.1 建表顺序

建议按依赖关系建表：

1. `admin_user`
2. `member`
3. `teacher`
4. `course_category`
5. `course`
6. `course_chapter`
7. `course_section`
8. `course_material`
9. `section_material`
10. `course_review`
11. `course_task`
12. `task_question`
13. `task_submission`

### 4.2 字段规范

- 主键统一 `bigint`
- 状态字段统一 `tinyint`
- 金额统一 `decimal(10,2)`
- 时间字段统一 `datetime`
- 文本大字段统一 `text`

### 4.3 通用字段建议

每张业务表尽量统一补齐：

- `id`
- `created_at`
- `updated_at`
- `created_by`
- `updated_by`
- `deleted`

### 4.4 索引建议

- 手机号、邮箱、分类父ID、课程教师ID、课程分类ID、评价课程ID、提交记录任务ID都要建索引
- 唯一约束建议用于：
  - `member.mobile`
  - `teacher.mobile`
  - `teacher.email`
  - `course_review(course_id, member_id)` 可按业务设唯一

## 5. 接口开发流程

每个模块统一按下面顺序推进：

1. 先写表结构和业务枚举
2. 再写 `entity / mapper / service`
3. 再写 `DTO / VO / controller`
4. 最后补参数校验、权限校验、单元测试、接口文档

建议每个接口都至少覆盖以下内容：

- 请求参数校验
- 数据存在性校验
- 权限校验
- 状态流转校验
- 返回 VO 脱敏
- 异常场景返回码

例如课程上架接口，至少校验：

- 课程是否存在
- 教师是否存在且启用
- 分类是否有效
- 是否至少存在一个章节或小节
- 当前用户是否有权限操作该课程

---

## 6. 联调顺序建议

为了避免前后端互相等待，建议这样联调：

1. 先联调登录与鉴权
2. 再联调教师、分类这些基础下拉数据
3. 再联调课程新增与课程详情
4. 再联调章节树、资料列表、评价列表
5. 最后联调考试/作业

原因：

- 登录和权限是所有接口的入口
- 教师和分类是课程表单的前置依赖
- 课程详情是前台核心页面，尽早稳定收益最大
- 如果新增“小节级资料”，建议放在课程章节联调之后、考试/作业之前

---

## 7. 测试流程

### 7.1 单元测试

至少覆盖：

- 登录密码校验
- 分类树构建
- 课程上架校验
- 客观题自动评分
- 重复评价校验

### 7.2 接口测试

建议使用 `Postman` 或 `Apifox` 建测试集合，按模块维护：

- 认证模块
- 会员模块
- 教师模块
- 课程模块
- 资料模块
- 评价模块
- 考试/作业模块

### 7.3 验收测试

按业务链路验收，不要只测单接口。

建议至少走通这几条链路：

1. 管理员创建教师 -> 创建分类 -> 创建课程 -> 新增章节 -> 上架课程
2. 学员注册登录 -> 查看课程 -> 查看章节 -> 下载资料 -> 提交评价
3. 管理员创建考试 -> 配题 -> 学员提交 -> 后台批改 -> 学员查看成绩

---

## 8. 里程碑建议

### 里程碑一：基础框架可运行

- 完成项目初始化、数据库连接、统一返回、异常处理、登录认证

### 里程碑二：课程后台可维护

- 完成教师、分类、课程、章节模块

### 里程碑三：课程前台可展示

- 完成前台课程列表、详情、评价、资料

### 里程碑四：学习考核闭环

- 完成考试/作业、提交、批改、成绩查询

---

## 9. 开发排期建议

如果是 1 到 2 名后端开发，建议按下面节奏推进：

| 周次 | 目标 |
| --- | --- |
| 第1周 | 项目初始化、登录鉴权、通用框架 |
| 第2周 | 教师、会员、分类模块 |
| 第3周 | 课程基本信息、章节模块 |
| 第4周 | 课程详情聚合、资料、评价 |
| 第5周 | 考试/作业、提交、批改 |
| 第6周 | 联调、修复、补测试、上线准备 |

---

## 10. 当前最建议的落地顺序

如果你下一步就要正式开始写代码，建议直接按下面顺序做：

1. 建立 Spring Boot 工程和基础依赖
2. 建 `member / teacher / course_category / course` 四张核心表
3. 完成管理员登录和 JWT 鉴权
4. 完成教师、分类、课程基本信息接口
5. 再补章节、资料、评价
6. 最后做考试/作业

这样可以最快把“课程平台后端骨架”搭起来，后续无论接后台管理端还是学员端都比较顺。
